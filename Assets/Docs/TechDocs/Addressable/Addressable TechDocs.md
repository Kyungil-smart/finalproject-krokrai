# Addressable

## 어드레서블 
- 에셋에 붙이는 문자로된 Key를 사용하여 그 에셋의 Key로 요청을 하면 필요한곳에 에셋을 전달해주는 역할
- 즉, 유니티에서 제공하는 에셋 관리 시스템으로 에셋마다 문자열 주소(Address)를 붙여서 필요한 시점에만 로드하고, 다 쓰면 해제(Release)할 수 있게 해준다

### 사용 하는곳
- 게임을 설치할 때, 플레이스토어나 앱스토어에서는 게임이 200MB정도로 빠르게 설치가 되지만, 실제로 게임에 들어가면 리소스 파일을 다운로드 하면서 1~2GB정도의 파일을 추가적으로 다운로드 하게되는데 이런식으로 게임파일과 챕터나 지역이나 레벨에 따라서 게임의 리소스를 분리하는것이다.

### 장점
- 어드레서블을 활용하여 게임을 제작하게 되면, 실제로 앱 스토어의 심사를 거치지 않고, 서버에 존재하는 에셋만 교체하는 방식으로 업데이트가 가능하다.
- 메모리 최적화: 안쓰는 에셋들을 메모리에서 즉시 해제할수있다.
- PC버전이 존재하는 게임의 경우 PC용 고화질 텍스처와 모바일용 저화질 텍스처를 같은 주소로 관리해서 유저들이 사용하는 플랫폼에 따라서 에셋을 로드할 수 있다.

### 어드레서블과 기존 방식의 차이점
|-|기존 방식|Addressable|
|:---:|:---:|:---:|
|로딩 시점|씬 로드 시 전부|필요할 때만|
|메모리 관리|수동/어려움|Release로 명확하게|
|원격 배포|불가|CDN 연결로 가능|
|에셋 참조|경로 의존|주소로 자유롭게 가능|
|빌드 크기|전체 포함|필요한 것만|

## 어드레서블의 핵심 키워드
- Address
- Group
- Label

### Address(주소)
---
- 에셋에 붙이는 문자열 이름표.
- 실제 파일 경로와 무관하게 직접 이름을 지정하고, 해당 에셋이 필요한 곳에서 지정한 주소로 호출해서 사용한다.

예시)
- Assets/Prefabs/Enemies/Goblin.prefab → 주소: "Monster_Goblin"
- Assets/UI/Textures/MainMenu.png      → 주소: "UI/MainMenu"

### Group(그룹)
---
- Address가 붙은 에셋들을 묶는 단위.
- 같은 그룹의 에셋들은 하나의 번들 파일로 묶인다.

```
예시)
[Chapter1_Assets 그룹]       [UI_Assets 그룹]
  ├── "Monster_Goblin"         ├── "UI/MainMenu"
  ├── "Monster_Orc"            └── "UI/HUD"
  └── "Stage1_Map"
```

→ Chapter1이 필요하면 Chapter1_Assets 그룹만 다운로드

→ Chapter1이 끝나면 Chapter1_Assets 그룹째로 메모리 해제 가능


### Label(레이블)
---
- 에셋에 붙이는 커스텀 스티커.
- 하나의 에셋에 여러 레이블을 붙일 수 있고, 레이블 이름으로 호출하면 그 레이블이 붙은 에셋이 모두 로드된다.


```
예시)
"Monster_Goblin"  → 레이블: "enemy", "chapter1"
"Monster_Orc"     → 레이블: "enemy", "chapter1"  
"Monster_Dragon"  → 레이블: "enemy", "chapter2"
"Stage1_Map"      → 레이블: "map",   "chapter1"
```

→ "enemy" 로 호출 시   : Goblin, Orc, Dragon 전부 로드

→ "chapter1" 로 호출 시: Goblin, Orc, Stage1_Map 전부 로드

[Group vs Label 차이]
- Group  = 에셋이 어느 상자에 담겨있냐
- Label  = 에셋이 어떤 특징을 가지고 있냐

## 동기 / 비동기 비유 예시

### 동기
- 카페에서 직접 기다리기
```
손님: 아메리카노 주세요!
카페: (커피 만드는 중...)
손님: (아무것도 못하고 가만히 서있음)
카페: 나왔습니다!
손님: 감사합니다!(이제서야 다른 행동 가능)
```
- 게임으로 치면 에셋을 로드하는 동안 게임 전체가 멈춰서 화면이 버벅거리거나 프리징 현상이 발생

### 비동기
- 진동벨을 받고 자리에서 기다리기
```
손님: 아메리카노 주세요!
카페: 진동벨 드릴게요~
손님: (자리에서 핸드폰도 보고, 친구랑 얘기도 가능)
카페: 주문하신 아메리카노 나왔습니다.(진동벨 울림)
손님: 감사합니다!(커피 수령 후 마시기)
```
- 게임으로 치면 에셋을 로드하는 동안에도 게임은 계속 돌아가고, 로드가 완료되면 에셋을 사용한다.

### 비동기를 사용하는 이유
- 에셋이 로컬에 있을 수도 있고, 서버에서 다운로드 해야 할 수도 있다.
- 다운로드하는 동안 게임이 멈추면 안되기 때문에 비동기가 필수이다. 

```csharp
// 동기 방식 - 에셋 로드 완료까지 게임 멈춤 (Addressable에선 거의 안 씀)
var obj = Resources.Load<GameObject>("Monster");  // 여기서 게임이 멈춤

// 비동기 방식 - 게임 계속 돌아가면서 에셋 로드
var handle = Addressable.LoadAssetAsync<GameObject>("Monster");
await handle.Task; // 에셋이 로드 될 때까지 다른 행동 가능
// ----> 여기부턴 로드 완료된 에셋을 사용
```

## 어드레서블 - 이번 프로젝트에서 사용하게 될 경우

- 컴포넌트화
- 이미지나 메모리를 직접적으로 관리 / 처리
- 데이터가 필요한경우 데이터를 받아와서 전달해줌
- 어드레서블이 매니저 역할을 함


- 예시) 이미지를 줘! 하면 어드레서블이 이미지를 가져오는 역할을 하기
- 의도) 이미지를 첫 로딩할때 딜레이가 있는데 그걸 고려해서 만들기
